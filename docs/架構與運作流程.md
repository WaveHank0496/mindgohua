> 寫於 2026-09-20，對應 `main` 的 `3251a51`（八個 PR 全部合併之後）。
>
> **這份文件的對象是你**（專案作者，不讀程式碼）。目標是讓你在不打開任何 `.kt` 檔的情況下，
> 知道這個 app 由哪些零件組成、一次打斷是怎麼發生的、以及**哪些東西雖然還在但已經沒在跑**。

## 0. 三十秒版本

```
你在滑 IG
   ↓
每 2 秒問一次系統：「現在前景是哪個 app？」        ← UsageStatsDetector
   ↓
「是 IG，而且已經連續 10 分鐘了」                  ← SessionEngine（純邏輯狀態機）
   ↓
蓋一隻全螢幕的貓上去                               ← OverlayController
   ↓
你按「停下來」或「再滑 5 分鐘」
```

中間那一層（`SessionEngine`）**完全不碰 Android**，所以它是整個專案唯一被測試徹底覆蓋的部分。

## 2. 一次打斷，從頭到尾

### 第 1 步：誰在前景？

`detect/UsageStatsDetector.kt`（203 行）

向系統的 `UsageStatsManager` 要「app 前景切換事件」。**拿到的只有「哪個 app、從幾點到幾點」** ——
沒有畫面內容、沒有你看了什麼。

輪詢間隔由 `detect/PollingPolicy.kt`（95 行）決定，這是省電的關鍵：

| 狀況 | 多久問一次 |
|---|---|
| 螢幕關著 | **完全不問**（輪詢停止） |
| 螢幕開著、但不在目標 app | 6 秒 |
| 正在目標 app 裡 | 2 秒 |

> ⚠️ **一個誠實的說明**：系統送來的事件流涵蓋**所有** app，程式讀完之後才丟棄不是目標的那些。
> 這是「讀了才丟」，不是「根本沒讀」。舊版曾經靠無障礙服務做系統層過濾，
> 但那個機制隨 Mode B 一起移除了（見第 6 節）。

### 第 2 步：算時間，決定要不要打斷

`core/SessionEngine.kt`（224 行）

**這是整個專案的心臟，而且它完全不依賴 Android** —— 吃事件、吐指令，時間由呼叫端傳入。
所以它能用一般單元測試把所有規則釘死（18 個測試）。

它管三個時間：

| 設定 | 預設 | 意思 |
|---|---|---|
| **連續使用超過** | **10 分鐘** | 超過就叫貓。有研究依據，見 `SPEC-下一階段.md` |
| **切出去多久算同一段** | 10 秒 | 瞄一眼通知再回來，計時不該被洗掉 |
| **解除後多久不再打斷** | 5 分鐘 | 按「再滑一下」買到的時間 |

**一個重要的行為修正**：使用者看到貓之後**直接離開目標 app**，會得到跟按下按鈕一樣的待遇
（計時歸零 + 發冷靜期）。原本的寫法會在他切回來時立刻再跳一次貓 ——
等於懲罰了我們最想鼓勵的行為。

### 第 3 步：蓋貓

`overlay/OverlayController.kt`（329 行）

用 `TYPE_APPLICATION_OVERLAY` 疊一張全螢幕的圖。防馴化設計有兩層：

1. 貓出現後 **3 秒內兩顆按鈕都不能按**（可調 0–3 分鐘），畫面上有倒數
2. 「再滑 N 分鐘」那顆要**按住 2 秒**；「停下來」單擊即可 ——
   **不該讓做對的事比較費力**

**返回鍵有兩道防線**（因為 targetSdk 36 之後平台行為改變了）：

- `dispatchKeyEvent` 攔截 `KEYCODE_BACK`（API 30–32 只能靠這個）
- API 33+ 另外註冊一個空的 `OnBackInvokedCallback`

> 查過 AOSP 原始碼：Android 16 上 overlay 視窗**其實還是收得到**返回鍵
> （因為它沒有 Activity，系統查到「沒有 callback」之後會主動注入一顆真的返回鍵）。
> 但那是**沒有任何文件承諾的平台 fallback**，所以兩道都做。

### 第 4 步：串起來的那個服務

`service/GatekeeperService.kt`（559 行）

常駐的 Foreground Service。Android 規定它必須顯示一則通知 —— 那不是我們想常駐，是規則。

它另外做兩件容易被忽略的事：

- **螢幕關閉時主動結束 session**。不然手機放口袋會被算成一直在滑，解鎖瞬間跳出一隻貓。
- **心跳**：每 60 秒蓋一次時間戳。被系統殺掉時時間戳就停住，下次啟動一比對就知道死了多久，
  並主動發通知告訴你。**這個 app 的失效方式是靜默的**，沒有這個你不會發現。

## 3. 資料存在哪裡

| 存什麼 | 在哪 | 會不會離開手機 |
|---|---|---|
| 你的設定 | `settings/SettingsStore.kt`（DataStore） | ❌ |
| 服務存活時間戳 | `stats/SurvivalLog.kt`（每 60 秒） | ❌ |
| 當機紀錄 | `diagnostics/CrashLog.kt` | 只有**你主動匯出**時 |
| 前景 app、滑動時間點 | **不存**，判斷完就丟 | — |

**沒有任何東西能離開這支手機，因為這個 app 沒有網路權限。**

## 4. 權限清單

| 權限 | 為什麼要 |
|---|---|
| `PACKAGE_USAGE_STATS` | 知道哪個 app 在前景、待了多久 |
| `SYSTEM_ALERT_WINDOW` | 把貓蓋在其他 app 上面 |
| `FOREGROUND_SERVICE` + `_SPECIAL_USE` | 服務要能一直跑 |
| `POST_NOTIFICATIONS` | Android 規定常駐服務要有通知 |
| `RECEIVE_BOOT_COMPLETED` | 開機後把服務接回來 |

> 📌 manifest 裡**還有一行 `INTERNET`，但那是 `tools:node="remove"`** ——
> 它的作用是叫建置工具**強制移除**任何第三方函式庫偷偷加進來的網路權限。
> 那不是宣告，是相反的東西。掃到它不用緊張。

**已經刪掉的兩個**：
- `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` —— Play 對它有白名單，「螢幕使用時間管理」不在上面
- `BIND_ACCESSIBILITY_SERVICE` —— 隨 Mode B 一起移除

## 5. ⚠️ 已經在程式碼裡、但目前沒有在跑的東西

這一節最重要。**這些東西存在會讓人誤以為功能還在。**

### 5.1 首次引導（onboarding）—— 996 行，零入口

`ui/onboarding/` 底下五個檔案（438 + 288 + 156 + 74 + 40 = **996 行**），
有 **52 個測試全部通過**，但是：

- `OnboardingScreen()` **沒有任何地方呼叫它**
- `MainActivity` 裡連 import 都沒有

所以它是一整塊「完整、獨立、但沒有門」的程式碼。**使用者走不到，所以現在不會造成傷害。**

**但絕對不要在修好之前接上去**，它有兩個會讓使用者卡死的問題：

| 問題 | 後果 |
|---|---|
| `onToggleTarget` 只寫 DataStore，**沒有回寫 `targetCount`** | 使用者**永久卡在選 app 那一步**（那一頁沒有次要出口） |
| `withPermissions` **零呼叫者** | 「從系統設定回來自動前進」不會發生，按主按鈕只會一直跳設定頁 |

### 5.2 滑動節奏演算法 —— 205 行，刻意保留

`core/ScrollRhythmAnalyzer.kt`（132 行）與 `core/ItemAdvanceCounter.kt`（73 行）
**沒有任何生產程式碼呼叫它們**，但有 19 個測試還在跑。

**這是刻意的**：它們是純演算法、不需要任何權限、零審核風險。
未來若要回來做 Mode B 不必重寫，而測試是這些演算法**唯一剩下的規格**。

### 5.3 統計與 HUD —— 有骨架，沒有資料來源

`stats/DailyStatsStore.kt`（88 行）、`overlay/CounterHud.kt`（68 行）。

原本的資料來源是無障礙事件的清單位置欄位，隨 Mode B 一起消失了。
現在 `showHudIfNeeded()` 無條件不顯示、計數迴圈也無條件不啟動 ——
否則舊使用者會看到一個**永遠不動、而且沒有開關能關掉**的浮層。

設定頁保留了一顆「清除先前的計數紀錄」，因為當初正當化「寫入磁碟」的理由
就是「使用者可以自己清除」，刪掉入口等於片面收回承諾。

## 6. 已經刪掉的：Mode B（無障礙服務）

v1 **完全移除**，不是隱藏。

**為什麼不能只從 UI 隱藏**：Play 掃的是你上傳的安裝檔裡的設定檔，不是 app 的畫面。
只要那個服務宣告還在，就會觸發「無障礙用途宣告」審查 —— 那是目前拒絕率最高的類別之一。

刪掉的東西：服務本體、偵測器、設定檔、manifest 宣告、兩條字串、權限查詢函式、
設定頁的五張卡片。`MainScreen.kt` 因此從 1,426 行降到 1,042 行。

**現在有一條測試守著它**：`PrivacyInvariantTest` 會斷言 manifest 完全不含無障礙宣告，
任何人加回來就會紅燈。

## 7. 測試覆蓋在哪裡

| 測試數 | 對象 | 說明 |
|---|---|---|
| 29 | onboarding 流程 | 邏輯層完整，**但 UI 層 438 行零測試** |
| 24 | 時間輸入解析 | 全形數字、溢位、範圍夾值 |
| 18 | Session 狀態機 | 門檻、冷卻、冷靜期、「逃走」的行為 |
| 14 | onboarding 文案 | |
| 13 × 3 | 存活提醒 / app 清單 / 設定預設值 | |
| 12 | 各廠牌背景管制對照 | |
| 11 + 8 | 滑動演算法（**目前沒人呼叫**） | |
| 10 | 輪詢策略 | 省電規則 |
| 6 | **隱私不變量** | 見下 |
| 其餘 | 換日、當機紀錄 | |

**`PrivacyInvariantTest`（6 個）是最特別的一組** —— 它不測功能，測的是**承諾有沒有被違背**：

- manifest 不得宣告 `INTERNET` / `ACCESS_NETWORK_STATE`
- 必須保留強制移除 INTERNET 的那一行
- 不得宣告任何無障礙服務
- 不得引入需要網路的函式庫
- 不得備份任何資料（含 Android 11 的舊路徑）
- **隱私文案不得宣稱做不到的事**

最後那一條是後來補的。移除 Mode B 的時候，兩句「曾經為真」的話在沒有任何人動到它們的
情況下變成了不實陳述，而 146 個測試一個都沒紅 —— **是外部審查才發現的**。
